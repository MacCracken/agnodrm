# Audit — 2026-11-06 (1.8.1)

The rest of the local 1.8.x work got one independent review, given the code and systemd's source and not the author's reasoning.
It found **4 HIGH, 3 MEDIUM and 5 LOW**, and every one was confirmed against the source before it was repaired. One of the HIGH
was in the new `bootctl --json` reader. The other three were older, and it kept them. All of this code passed its tests, the
suite then at 93 of 95 mutants, and a read-only run against a real `bootctl` 262. None of that showed the JSON shape was
wrong, because the host it ran on has no addons. **The reader was written from a `null`.**

Every finding below was reproduced on `bootctl` 262 over a private `--root` tree, and those runs were repeated after the
repair. Nothing here wrote to a host's boot partition, its firmware, or its journal.

### What it took to get the shape right

Real output, from a tree with a global addon, a local addon, a sysext and a credential, captured verbatim and now the test's
fixture. `addons` is `null` when there are none and `extras` is absent, which is all a host without them ever shows:

```json
{"type":"type2","id":"u.efi","options":"\"quiet\" 1 \"rw\"","linux":"/EFI/Linux/u.efi",
 "addons":[{"globalAddon":"/loader/addons/global.addon.efi","options":"rd.break"},
           {"localAddon":"u.efi.extra.d/local.addon.efi","options":"systemd.run=/evil"}],
 "cmdline":"\"quiet\" 1 \"rw\" rd.break systemd.run=/evil",
 "extras":["/loader/addons/global.addon.efi","u.efi.extra.d/sys.sysext.raw","u.efi.extra.d/secret.cred",
           "u.efi.extra.d/local.addon.efi"]}
```

**Do not write a parser from what a host printed.** Read the producer to its end, and take a fixture from a tree that has
everything the format can hold.

### The repairs

- **The file wins (F-79, F-81).** `bootctl` is what a tool believes and the file is what boots, so a file's boot keys now replace
  an entry's. `options` and `extra` hold what both say, since only bootctl knows what an addon adds, and where they agree that
  is one copy. So a line can read twice over and a validator sees more than boots, which is the direction to err.
- **Every UKI is accounted for (F-80, F-90).** `/EFI/Linux` under each of the three roots is read as systemd-boot reads it: an
  `.efi` in any case, not hidden, not `auto-*`. Each entry answers for one file, and an unreported one is added with no options,
  since this library does not read a UKI. A validator refuses a null line, so it is seen and not passed.
- **A UKI's line is the UKI's (F-82, F-86).** It keeps its quotes and is mangled as sd-stub does, on both the JSON and text paths.
- **`fuse_mount` has no deadline (F-87).** It is the one tool that keeps none, on purpose, and SECURITY.md says so.

### Tests and mutation

The suite pins all of the above, with real output as the fixture.

- **Unit:** 150 mutants, 148 caught. The two left need a host setting (`vm.memfd_noexec=2`, or a kernel before 6.3). A leak of one
  mapping on an `Err` path was read, not tested.
- **Fuzz:** 28 mutants across the four harnesses this release touched, 24 caught. Two do not change a result. The other two,
  bracket matching and the depth limit, are caught by the unit suite instead, because random text rarely nests 65 levels.
- **`fuzz/fuse_parse.fcyr`** crashed on its first run with a stricter check, and the bug was in the check. A line opening with a
  space has no device, and `\012` decodes to a real line end, as the kernel means it to. Both are now in the model.

### Residual, accepted

- **F-83: text is still a fallback.** It runs only where `--json=short` fails, and bootctl's text can be reshaped by what a UKI
  holds. A UKI that loses its key that way gets it back from `/EFI/Linux`, and the file wins for Type #1, so what is left is
  the display fields. Refusing text would cost every bootctl too old to know the flag.
- **A UKI's own command line is unknown** unless bootctl reports it. Reading one is PE parsing, which this library does not do.
- **A counted UKI, or a profile of one, shows twice,** once under the name bootctl gives it and once under its file's. That errs
  toward showing it.
- **`timeout` past nine digits leaves the default.** systemd-boot would take it. Nothing depends on a wait of 30 years.
- **The memfd path's `MFD_NOEXEC_SEAL` and its fallback have not run**, as at 1.8.0.
